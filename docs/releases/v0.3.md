# v0.3 candidate — release gates

This is the working increment for AD-PRM-20261111-007, superseding unexecuted 006.
It is **not a published v0.3.0 release**. Final implementation/capacity status and exact identities
are in [result 007](../results/AD-RES-20261111-007.md).

Delivered: smaller eager FULL partition allocation by reusing immutable values; early bounded
admission; positive configurable number/body policies; consistent 413/503 with Retry-After;
readiness/graceful shutdown; multi-stage Docker and single/scaled Compose; official k6 arrival,
concurrency and validation scenarios; paired JMH and native/full-container HTTP evidence.
The success schema, numerical policy, defaults, warnings, global statistics, order and duplicates
remain. Swagger still requires dev **plus** SWAGGER_ENABLED=true.

Demo defaults: active=1, max numbers=2,000,000 inclusive, body=64 MiB inclusive. These deliberately
restrict formerly unlimited input. Ten total 2M FULL requests/second carry roughly 99 MB/second
of body payload **each direction**, before protocol overhead. Evaluate IQR, Z_SCORE and mixed
separately, with unchanged full normalValues.

Root clean verify must pass zero-missed LINE/BRANCH, unit + real HTTP integration, format/lint
and strict JavaDoc. Separate harness/tooling verification and actual packaged-container checks
are also mandatory. Load must meet the target without sustained rejection, timeouts, drops or
accumulating backlog, inside the declared CPU/RAM budget. Three serial samples do not establish p99.

If any gate fails or cannot execute, preserve incomplete work on its feature branch and report
PARTIAL. Do not merge to released master or create release/v0.3 / v0.3.0. Earlier release refs
remain immutable. A later successful authorized release must merge through develop to tested
master, create new refs and verify actual CI/reports on the exact release SHA.
