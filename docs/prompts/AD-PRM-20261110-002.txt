RELEASE v0.1: IQR AND API
Algorithm identifier: IQR.
Quartile convention: median of lower/upper halves after sorting a COPY. For odd n, exclude the overall middle element from the two halves only; still classify every original value.
Even-sized half: arithmetic mean of the two middle values. Preserve this convention across future optimizations.
IQR = Q3 - Q1.
lowerBound = Q1 - threshold * IQR.
upperBound = Q3 + threshold * IQR.
Anomaly iff value < lowerBound OR value > upperBound. Equality with a boundary is normal.
Default IQR threshold: 1.5. Finite non-negative thresholds, including zero, are valid.
n=1: explicitly define Q1=Q3=the value.
n=2/3: apply median-of-halves normally.
For 1<=n<4, return a successful result with warning code SMALL_DATASET.
For n=0, return HTTP 200 with status NO_DATA, empty result lists, and explicitly null statistical fields.
For n>=1, status is COMPLETED, even when no anomalies exist.
IQR=0 is valid; follow the same strict-boundary formula without special invented widening.

POST /api/v1/anomaly-detection
Consumes application/json.
algorithm is required and uses documented canonical identifiers.
data is a required numeric array. An empty array is valid; absent/null data is invalid.
threshold is optional: omission invokes the selected algorithm's default, but explicit null is invalid. Do not collapse these cases.
Reject null elements, nonnumeric values, numeric strings, non-finite values, and wrong JSON shapes. Validate algorithm/parameters even for empty data.
Reject undocumented fields with a clear 400, rather than silently accepting misspellings.

Example request:
{"algorithm":"IQR","threshold":1.5,"data":[10,12,11,13,12,14,11,13,12,100]}

Example required IQR statistics/partitions:
q1=11, q3=13, iqr=2, lowerBound=8, upperBound=16
anomalies=[100]
normalValues=[10,12,11,13,12,14,11,13,12]

Keep IQR fields flat at the top level, matching the task. Add algorithm, effective threshold, status, and warnings.
Use HTTP 200 for successful calculations including small/empty datasets; 400 for invalid requests/unsupported algorithms; 415 for unsupported content type; 422 for finite valid inputs whose calculations cannot be represented safely; 500 for unexpected internal errors. Preserve proper framework status codes such as 405.
Use consistent RFC 9457 Problem Details errors with a stable error code. Do not expose stack traces.
Do not round statistics before classification. Guard arithmetic overflow/non-finite computed statistics, not just input values.

RELEASE v0.2: Z-SCORE
Add Z_SCORE as a new detector through the existing Strategy/registry mechanism. Preserve IQR behavior, endpoint and request fields.
Z = (x - mean) / standardDeviation; anomaly iff abs(Z) > threshold.
Use POPULATION standard deviation: variance divisor n. Document this convention.
Default Z_SCORE threshold: 3.0, with finite non-negative configurable thresholds.
Use a numerically stable method such as Welford for statistics and a subsequent classification pass.
For zero variance, return all values as normal, without division by zero, and include ZERO_VARIANCE. For 1..3 values also keep SMALL_DATASET.
For empty Z_SCORE data, use NO_DATA, empty lists and null mean/standardDeviation.
The Z_SCORE response has the common fields plus mean and standardDeviation. Do not fill it with irrelevant IQR statistics.
Document the algorithm-specific response alternatives using OpenAPI oneOf/discriminator on algorithm, with unambiguous algorithm values.
Different algorithms may give different answers on the same data. Do not force Z_SCORE to flag 100 in the original ten-value IQR example when threshold 3 does not warrant it.
Do not implement future algorithms.
