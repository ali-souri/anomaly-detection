# v0.3 architecture decision

Status: implemented candidate under AD-PRM-20261111-007; release readiness depends on
[actual capacity evidence](../load-tests/README.md). Historical recommendations remain in immutable
[result 003](../results/AD-RES-20261110-003.md). Prompt 007 supersedes unexecuted 006. The owner now
requires **10 complete successful 2M FULL requests/second total**, separately IQR, Z_SCORE and
50/50 mixed. No owner latency SLO was supplied.

## Selected increment

Keep one stateless modular Spring application with Strategy, immutable registry and constructor
injection. IQR's general copy-sort costs O(n log n), Z_SCORE's two passes O(n); both retain O(n)
memory and classify a complete global dataset. Parallel independent requests can improve aggregate
throughput; replicas do not make one global sort cheaper. Never average chunk quartiles or classify
chunks against unrelated local fences.

The smallest source-supported allocation change reuses existing immutable Double references from
validated snapshots in output partitions. Arithmetic remains primitive; eager FULL results,
ordering, duplicates and snapshots remain contractual. The matched paired experiment measured
**39.48% less B/op for IQR and 45.55% for Z_SCORE** at 2M MIXED. Both timing intervals overlap;
there is no established general speed gain. [Paired evidence](../benchmarks/v0.3/report.md).
A primitive-array model rewrite is unnecessary for this clear allocation benefit.

A pre-controller filter acquires an immediate semaphore permit before expensive body binding,
with no admission waiting queue. It retains the permit through synchronous response writing
and releases in finally. Spring before-body advice uses bounded JDK readNBytes before Jackson,
including chunked bodies/trailing whitespace. Number count is checked before converting the
existing tree to a Double list. The additional bounded raw-body buffer and JSON tree must be
included in concurrent memory measurements; core B/op does not establish a safe heap limit.

Positive demo defaults: active=1, inclusive 2M numbers and 64 MiB bytes. HTTP 503 has ADMISSION_FULL
and Retry-After: 1; 413 has INPUT_TOO_LARGE. These intentionally replace historically unlimited
acceptance with provisional operational policies. Tomcat's rejected-body discard allowance is
bounded too, allowing valid large uploads to receive 503 without a premature connection reset.
A per-instance setting is not a cluster-wide limit.

## Deployment and target

Docker packages the same application with Java 21, readiness and graceful shutdown. The demo's
4 CPUs, 3 GiB container / 2 GiB heap leave native/thread headroom but are experiment settings.
Capacity uses a fixed budget and separately bounded official k6 generator, fully received bodies,
open arrival at 10 total RPS and separate success/rejection/error/timeout/drop counts. Successful
latency excludes fast rejections; timestamps expose completion/drain boundaries. Useful overload
behavior does not count as successful detection capacity.

Scale copies through nginx only after inspecting measured concurrent CPU/memory. The ceiling is
three application containers with OS/generator headroom. Publication requires all three workload
cases to meet the target without sustained rejection, timeouts, drops or growing backlog. A
favorable mix cannot hide IQR shortfall. Default capacity is separate from tuned scaling evidence.

## Deferred decisions

Independent algorithm services do not reduce sorting/allocation/JSON/network costs and add
deployment, transport and versioning overhead. RabbitMQ needs durable asynchronous job requirements.
Persistence needs retention/replay requirements. gRPC needs a measured benefit and cooperating
clients; short decimal JSON is not automatically larger than binary doubles. Authentication needs
identity/authorization and deployment-boundary requirements. None is implemented here.

The next experiment should isolate the measured bottleneck with an independent generator, profile
parse/sort/serialize/GC under a fixed budget and repeat all three open-arrival workloads. Reduced
output requires explicit owner/consumer agreement and preserves FULL defaults; it cannot be used
to claim this target. Stress/soak, remote networking and production tail-latency proof remain
separate. No follow-up work starts automatically.

## 008 delivered decision

Warmed 007 JFR execution samples consistently assign 42.73–45.96% of IQR Java samples to boxed
sorting. One local primitive sort workspace reduces matched 2M core mean 657.289→201.915 ms/op;
B/op remains nearly constant. Full mathematical/ordering/signed-zero/HTTP checks and exact coverage
pass. This is the only production optimization; no primitive model or parsing rewrite was added.
The 008 target still fails (339/348/335 successes per 60 seconds for IQR/Z_SCORE/mixed), so the
feature is not released. A separate scaled candidate diagnostic assigns about 65.73% of Java
samples to tree creation, numeric-list conversion and serialization. These are sampled stack
frequencies, not precise phase durations. The next scoped experiment is bounded direct request
parsing with all strict validation/limit/error contracts tested; serialization remains material.
No automatic continuation or guarantee of reaching the target is implied.
